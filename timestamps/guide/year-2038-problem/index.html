The year 2038 problem

A signed 32-bit Unix timestamp runs out on 19 January 2038 at 03:14:07 UTC.

On Tuesday, 19 January 2038, at 03:14:07 UTC, Unix time reaches 2,147,483,647, the largest number a signed 32-bit integer can hold. One second later systems that store Unix time in a signed 32-bit integer wrap around to -2,147,483,648, which they read as 1901-12-13 20:45:52 UTC, in December 1901. Software that stores time this way can then show wrong dates, refuse to run or crash.

Who is affected

Programs, file formats and embedded devices that store time in 32 bits are affected. Modern operating systems and languages use 64 bits for time, which will not run out for about 292 billion years, so most current software is safe. Old embedded systems, some database columns (such as the TIMESTAMP type of some database systems), and old file formats are where the risk lives.

What to check

Look for time stored in an int of 32 bits, for dates later than 19 January 2038 that your system accepts (such as a 30-year loan, a policy or a subscription ending after that date) and for systems you cannot upgrade. Test them by entering the date 20 January 2038. The converter on this site shows the exact wrap-around moments; the milestones page gives them in a table.

The unsigned limit

If the 32-bit number is unsigned, the counter reaches 4,294,967,295 on 2106-02-07 06:28:15 UTC, so such systems last another 68 years.
